# 01 · 项目介绍与架构

> Smart VCard v0.1.0 · Indigo Grid Edition（靛格制签）
> 本文与 `src/` 源码严格对齐，描述项目定位、范围、技术形态、模块结构与关键设计决策。

## 一、项目是什么

Smart VCard 是一个**纯浏览器运行的 vCard 名片工坊**：把联系方式整理成一张可扫码、可保存、可打印的数字名片，并同时导出为联系人文件、位图、矢量图与矢量 PDF。

它解决的是「线下交换联系方式」这一具体场景：

- 名片印二维码，对方用系统相机扫码即可直接存联系人；
- 或在微信里发一条链接，对方点开就能保存；
- 或把成品名片打印 / 交印刷店，作为纸质名片的补充。

核心承诺：**本地优先、中英双语、不上传、不注册、无埋点**。所有计算都在浏览器里完成。

## 二、目标用户与场景

| 用户 | 场景 | 关键诉求 |
|---|---|---|
| 商务 / 销售 | 展会、拜访、会议 | 当场出码，不依赖网络与账号 |
| 设计与品牌从业者 | 需要一张「像作品」的名片 | 版式可控、可打印、可导出矢量 |
| 小微企业主 | 给团队统一名片样式 | 品牌简称 / Logo / 一句话可配置 |
| 普通用户 | 临时交换联系方式 | 不注册、不上传、手机可用 |

## 三、范围边界

### 本版必做（已完成）

- 中英双语表单与界面（键位一致，文案对齐由测试保证）。
- 实时名片校样与二维码生成（三种模块样式、五墨色 + 自定义取色）。
- 双通道二维码（网页链接 / 原生 vCard）。
- 交付闭环：.vcf / PNG(512·1024·2048) / SVG / **PDF(A6 矢量)** / 打印 / 复制 vCard / 复制二维码图片 / 系统分享。
- .vcf 导入回填（含多名片提示、LOGO/PHOTO 分流、引号参数、RFC 6868 转义）。
- localStorage 草稿（Logo 独立键，刷新不丢）。
- PWA 离线可用。
- 浅色单主题视觉体系「靛格制签」，无背景装饰。
- 102 项自动化测试（含像素级解码回环与静态隔离守卫）。

### 不实现

- 账号 / 登录 / 云端同步（与本地优先定位冲突）。
- 扫描统计、动态可改码、短链服务（零追踪）。
- 暗色主题、背景图片 / 渐变 / 纹理。
- 服务端任何组件。

### 待定（backlog）

- 家庭 / 工作双地址分区（需需求方确认）。
- 分享页联系信息默认遮罩。
- 人类可读 URL 参数分享。
- 二维码载荷逐字段截断（当前全局容量策略更稳）。

## 五、模块结构与分层

源码根为 `src/`，按职责分层，模块间使用相对导入，入口自洽（`index.html` → `./src/main.tsx`）。

```
src/
├── main.tsx              # 入口：Provider 装配、PWA 注册、全局错误兜底
├── App.tsx               # 路由表（懒加载）+ 全局错误覆盖层
├── index.css            # 「靛格制签」设计令牌（@theme）与 Tailwind 层
├── vite-env.d.ts        # Vite 类型声明
├── components/          # 通用 UI 组件
│   ├── Header / Footer / Layout        # 顶栏、页脚、布局骨架
│   ├── CardPreview / Field / Segmented / ConfirmDialog
│   ├── ImportDialog / ToastHost / Icon / LanguageToggle
│   └── generator/DeliveryPanel.tsx     # 工坊交付台（导出/复制/分享）
├── hooks/               # 副作用与状态钩子
│   ├── useDocumentHead   # 文档标题 / description
│   ├── useLocalStorage   # 持久化（固定 setter 身份，避免自动保存循环）
│   ├── useQrPreview      # 二维码状态化（容量错误等）
│   └── useToast          # 全局提示
├── i18n/
│   ├── index.ts          # i18next 初始化 + 语言检测
│   └── locales/{zh,en}.json
├── lib/                 # 纯逻辑层（无 React 依赖，可单测）
│   ├── vcard.ts         # vCard 3.0 写入器（CRLF / 75B 折行 / 转义 / TYPE 参数）
│   ├── vcardParse.ts    # vCard 解析器（折行 / 分组 / 参数 / RFC 6868）
│   ├── vcardTypes.ts    # 名片数据类型
│   ├── cardShare.ts     # 分享链接编解码（TextEncoder + base64url）
│   ├── qr.ts            # 二维码 SVG 渲染（墨迹 / 取景器 / 密度下限）
│   ├── pdf.ts           # 矢量 PDF 导出（A6）
│   ├── schema.ts        # Zod schema + FIELD_LIMITS 单一事实源
│   ├── text.ts          # 姓名排序等文本处理
│   ├── safety.ts        # URL / 文件名 / 输入消毒
│   ├── settings.ts      # 二维码样式设置与合并
│   ├── constants.ts     # 墨色预设、容量常量
│   ├── download.ts      # 文件下载工具
│   ├── toastContext.ts  # Toast 上下文
│   └── version.ts       # APP_VERSION / APP_EDITION（单一事实源）
└── pages/               # 路由页面
    ├── Home.tsx         # 首页：能力清单、三步流程、隐私承诺
    ├── Generator.tsx    # 制签工坊：表单 + 校样 + 交付
    ├── About.tsx        # 关于：设计原则、技术栈、许可
    ├── PublicCardView.tsx  # 分享页：扫码后的成品名片
    └── NotFound.tsx     # 404：返回首页
```

**分层原则**：

1. **lib 为纯逻辑层**：不依赖 React，所有业务规则（vCard 编解码、二维码渲染、校验、消毒）集中于此，由 `tests/` 直接覆盖，可脱离浏览器验证。
2. **hooks 封装副作用**：localStorage、剪贴板、文档头、Toast 等副作用收敛为可复用钩子，组件只消费状态。
3. **components / pages 只做编排**：页面与组件负责布局与交互，业务规则调用 lib，不重复实现。
4. **入口自洽**：`index.html` 引用 `./src/main.tsx`，`main.tsx` 装配 Provider 与路由，懒加载分包由 Vite 处理。

## 六、关键设计决策

1. **手写 vCard 3.0 写入器**：第三方库的 `;CHARSET=UTF-8`、CJK 姓名顺序、TYPE 参数缺失都会造成互操作问题；采用保守属性序 + CRLF + 75 字节折行 + 全量转义，最稳。
2. **双二维码载荷**：微信扫码器不认原生 vCard，故默认网页链接（数据在 URL `#` 片段，不发送给托管方）；系统相机场景切原生 vCard（LF 紧凑形态，降 QR 版本）。
3. **可扫性是工程约束**：模块墨迹填满单元、取景器实心、PNG 按目标尺寸光栅化 + 8px/模块密度下限；由 jsQR 像素级回环测试守底。
4. **自包含是承诺也是测试**：无第三方请求、无内联脚本、无 `console`；由静态隔离守卫测试在 dist 产物上持续断言。
5. **Logo 独立存储**：1MB 级 base64 不随击键自动保存骑行，也不被其覆盖；独立键 `smart-vcard-logo-v1`。
6. **视觉令牌单一事实源**：`@theme` 语义色角色 + 圆角 / 投影刻度，组件只消费令牌，浅色单主题。
7. **字段上限单一事实源**：`FIELD_LIMITS` 同时约束 schema 校验与草稿恢复，避免双源不一致。

## 七、视觉体系：靛格制签（Indigo Grid）

- 冷纸画布 `#f4f6fa`、墨蓝 `#16213a`、靛蓝主色 `#2b4acb`、松绿 / 琥珀辅色。
- 无衬线粗体标题；12–14px 圆角 + 柔和投影 + 1px 细线；编号徽标、胶囊标签、幽灵序号。
- 25 个图标统一为 2px 描边、圆角线帽的几何风格（`src/components/Icon.tsx`）。
- 功能零变更：所有 id / name / 选择器 / nonce / 对外契约保留；测试锚定的 lib 层输出不变。
