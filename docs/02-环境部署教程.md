# 02 · 环境部署教程

> Smart VCard v0.1.0 · 本文严格依据最终代码编写，所有命令在项目根目录执行。

## 一、环境要求

| 项 | 要求 | 验证命令 |
|---|---|---|
| Node.js | ≥22.15（测试脚本依赖 Node 同步 `registerHooks`） | `node --version` |
| npm | 10+（Node 22 自带） | `npm --version` |
| 操作系统 | Windows / macOS / Linux 均可 | — |
| 浏览器 | Chrome / Edge / Safari / Firefox 近两年版本 | — |
| 内存 | ≥4 GB（构建期约 512 MB） | — |

本项目**没有后端、没有数据库、没有密钥**。不需要 `.env` 文件，配置说明见根目录 `.env.example` 与本文第七节。

## 二、获取与安装

```bash
# 安装依赖（版本已由 package-lock.json 锁定）
npm ci        # 或 npm install
```

## 三、本地开发

```bash
npm run dev        # 开发服务器（默认 http://localhost:5173）
npm run typecheck  # TypeScript 类型检查（tsc -b）
npm run lint       # ESLint 静态检查
npm test           # 102 项自动化测试
npm run build      # 生产构建（tsc + vite + PWA + CSP 注入）
npm run preview    # 预览生产构建（默认 http://localhost:4173）
npm run icons      # 重新生成 PWA 图标（改品牌色后执行）
npm run archive    # 打包交付 zip（UTF-8 文件名，时间戳命名）
```

> CI 配置位于 `.github/workflows/`：`ci.yml` 在 Ubuntu / Windows / macOS 执行同一套门禁并构建 Docker 镜像冒烟；`release.yml` 在推送 `v*` Tag 时产出静态包与 GHCR 镜像。本地仍可按上述命令完整复现。

## 四、质量门禁（本地执行顺序）

安全守卫测试对 `dist/` 产物断言，因此**必须先构建后测试**：

```bash
npm run lint && npm run build && npm test
```

1. `npm run lint` — ESLint 零告警。
2. `npm run build` — 类型检查 + 生产构建（含 CSP 注入与 PWA 预缓存）。
3. `npm test` — 102 项测试，含对 `dist/` 的静态隔离守卫（无 dist 时守卫项自动跳过并提示）。

> 若跳过构建直接测试，dist 守卫项会被跳过；完整验证请按上述顺序执行。

## 五、构建产物结构

`npm run build` 生成 `dist/`：

```
dist/
├── index.html            # 内联 CSP meta（仅生产构建注入）
├── manifest.webmanifest  # PWA 清单（theme_color #2b4acb）
├── sw.js / workbox-*.js  # Service Worker（离线 precache）
├── favicon.svg / robots.txt / icons/*
└── assets/               # JS / CSS（哈希文件名，路由级懒加载分包）
```

## 六、托管（静态 / Docker）

产物为纯静态文件，`vite.config.ts` 中 `base: "./"` 支持任意子路径：

- **任意静态托管**（Nginx / COS / OSS / Vercel / GitHub Pages）：上传 `dist/` 全量即可。
- 应用使用 HashRouter（`#/`），托管方**无需 SPA rewrite 规则**。
- 首次访问后 Service Worker 预缓存全部产物，离线可用。

### Docker + Nginx（推荐）

```bash
docker compose up -d --build          # 构建并启动，默认 8088 -> 容器 80
curl -fsS http://127.0.0.1:8088/healthz
docker compose ps                     # 状态与健康检查
docker compose logs --tail=100 web    # 启动日志
```

- 端口可用 `SMARTVCARD_PORT` 覆盖：`SMARTVCARD_PORT=9090 docker compose up -d`。
- `Dockerfile` 为两阶段构建：`node:22-alpine` 里 `npm ci && npm run build`，`nginx:1.27-alpine` 托管 `dist/`。
- `deploy/nginx.conf` 已设置入口与 Service Worker 不缓存、哈希资源长缓存、`/healthz` 探活与基础安全响应头。
- 容器 `HEALTHCHECK` 与 CI 冒烟均访问 `/healthz`。

## 七、版本与配置位置（无 .env）

本项目不读取任何 `.env`。部署期配置均在代码中，修改位置如下：

| 配置 | 位置 | 当前值 | 何时修改 |
|---|---|---|---|
| 部署 base | `vite.config.ts` | `"./"` | 部署到自定义路径且希望使用绝对路径时 |
| PWA 主题色 / 背景色 | `vite.config.ts` | `#2b4acb` / `#f4f6fa` | 换品牌配色时（同步 `src/index.css` 令牌） |
| 应用版本号 | `src/lib/version.ts` 与 `package.json` | `0.1.0`（两处一致） | 发新版时 |
| 品牌与全部文案 | `src/i18n/locales/{zh,en}.json` | — | 改文案时（两语言键位必须一致，测试保证） |
| 二维码墨色预设 | `src/lib/constants.ts` | 靛蓝/墨蓝/松绿/石板/纯黑 | 调整预设时（键名需与 i18n 对应） |
| 字段长度上限 | `src/lib/schema.ts` `FIELD_LIMITS` | 单一事实源 | 增改字段时（编译期强制全覆盖） |
| PWA 图标 | `public/favicon.svg` + `scripts/make-icons.mjs` | 靛蓝体系 | 改品牌色后运行 `npm run icons` 重新生成 |

## 八、本机存储键（升级兼容）

浏览器 `localStorage` 中的键，全部是用户数据，不含密钥：

| Key | 内容 | 兼容性 |
|---|---|---|
| `smart-vcard-draft-v1` | 表单草稿（不含 Logo） | 沿用；恢复时按 `FIELD_LIMITS` 逐字段截断并剥离控制字符 |
| `smart-vcard-logo-v1` | Logo（上传的 base64 或远程 URL） | 首次启动自动迁移旧草稿内联 Logo |
| `smart-vcard-settings-v1` | 二维码样式 / 颜色 / 尺寸 / 模式 | 沿用 |
| `smart-vcard-lang` | 语言偏好 | 沿用 |

## 九、故障排查

| 现象 | 排查 |
|---|---|
| 页面空白并显示 `Render failed` | 全局错误覆盖层已打印堆栈；按栈定位（生产构建可对照 sourcemap 策略） |
| 分享链接无效 | 确认链接完整（`#/?v=` 在 hash 内）；超长 / 被截断的链接会显示引导页 |
| 二维码不可扫 | 检查载荷状态徽章；「内容过长」时缩短备注或切网页链接；PNG 过密会自动放大并提示 |
| PDF 导出失败 | 首击会动态加载 PDF 库，失败时重试或改用 SVG；检查浏览器是否拦截 blob 下载 |
| 复制二维码图片变为下载 | 浏览器无图片剪贴板能力时的既定降级，Toast 会说明 |
| 测试中 dist 守卫被跳过 | 先执行 `npm run build` 再 `npm test` |
| 改品牌色后图标不一致 | 运行 `npm run icons` 重新生成 `public/icons/*` |
| `npm test` 报 `ERR_MODULE_NOT_FOUND` | 测试脚本已通过 `scripts/node-test-resolver.mjs` 补全扩展名；确认 Node ≥22.15 |

## 十、交付包

```bash
npm run archive
# 输出：app_YYYYMMDD_HHMMSS.zip（项目根目录）
```

包含：`src/` / `public/` / `scripts/` / `tests/` / `docs/` / 根配置文件。**排除**：`node_modules`、`.git`、日志、zip 本身；任何 `.env` 与密钥目录均不进入交付包。
