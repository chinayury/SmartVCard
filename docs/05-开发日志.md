## 2026-11-15 · 迭代（v0.3.0 · 口令加密分享链接）

> 第三次迭代。主打落地上一轮 backlog 的 M2（Pagecrypt 思路）。README 测试计数与本节同步为 122。

### 一、调研与巡检（增量）

1. 调研：针对 M2 做先例核实——PageCrypt（MaxLaumeister）与 StatiCrypt 均以 WebCrypto AES-256-GCM + PBKDF2 做纯浏览器加密，验证了技术路线；但它们把密钥放进 URL fragment（单链便利、威胁模型弱）。本项目采用**口令独立渠道**模型：链接只带密文，口令当面/另行告知——「链接泄露但口令未泄露则数据不可读」。
2. Issues 巡检：开放 Issues **0 条**；`npm audit --omit=dev` 0 漏洞。

### 二、M2 口令加密分享链接

- **实现**：新增 `src/lib/crypto.ts`（envelope = salt 16B | iv 12B | AES-256-GCM(deflate-raw JSON)，PBKDF2-SHA256 310k 迭代派生密钥）；`cardShare.ts` 新增 `x` flag 与类型化 `SharePasswordRequiredError`；交付台新增口令输入（仅 URL 模式，UI 明示「切勿与链接同渠道发送」）；接收端新增口令解锁页（错误口令被 GCM 拒绝并如实提示）。
- **关键决策**：缺 WebCrypto 时加密请求**直接报错**，绝不静默降级为明文；口令不持久化（不进草稿/设置/备份）；加密优先于压缩（先压缩后加密，密文更紧凑且泄露信息更少）。
- **取舍**：口令不进链接是比 PageCrypt/StatiCrypt key-in-link 更强的威胁模型，代价是发送方需要第二个渠道传递口令——UI 文案把这个取舍讲清楚，不隐瞒。

### 三、验证记录（2026-11-15）

- `npm run verify` 全绿：lint 0、build 成功、**122/122** 测试（新增 crypto 5 项 + cardShare 加密集成 5 项：回环/信封结构/明文不泄露/密文随机化/错误口令/篡改/截断/缺口令类型化报错/URL hash 参数/d·p·legacy 不受影响）。
- 浏览器端到端（Chromium + vite preview）：设口令生成 `x` 加密链接（139 字符）→ 解锁页无明文泄露 → 错误口令拒绝 → 正确口令解锁完整名片。

### 问题闭环（现象 → 根因 → 解决方案）

#### D-01 Logo 自动保存抹掉已保存数据（P1）

- **现象**：上传 Logo 并点「保存并校样」后，再改任何字段，约 1.2s 后草稿自动保存把 Logo 抹掉；刷新即丢。
- **根因**：自动保存基于 `valuesJson`（`logoUrl` 恒置空以避免写 1MB base64），手动保存写入的含 Logo 草稿被下一次自动保存覆盖。
- **解决方案**：Logo 迁入独立键 `smart-vcard-logo-v1`；上传 / 粘贴 / 清除 / 导入四路同步；旧草稿内联 Logo 一次性迁移；粘贴 URL 的 Logo 经同步效应持久化。
- **验证**：浏览器实测：粘贴链接 → 自动保存 → 刷新保留；保存后再输入不丢；清空同步清除。

#### D-02 恢复值超出表单上限（P2）

- **现象**：导入 ORG 300 字符的第三方卡片，未触碰的字段亮「内容超出长度上限」。
- **根因**：`mergeWithDefaults` 统一 2048 截断，与 schema 逐字段上限（120/64/1000…）不一致。
- **解决方案**：`FIELD_LIMITS` 单一事实源（编译期约束覆盖全部字段），schema 与恢复共用；恢复时剥离控制字符。
- **验证**：schema 测试新增逐字段上限用例。

#### D-03 残缺地址写垃圾行（P1）

- **现象**：只填国家导出 `ADR:;;;;;;USA`，通讯录出现不可删的空地址行。
- **根因**：地址输出规则为「任一非空即输出」。
- **解决方案**：street 与 city 齐全才输出；补 `ADR;TYPE=WORK`。
- **验证**：vcard / roundTrip 专项用例。

#### D-04 导入超大文件文案误报（P2）

- **现象**：200KB .vcf（超 65,536 字符上限）报「未找到可识别的 vCard 属性」。
- **根因**：字节预检与字符上限分离，超限与「非 vCard」共用 null 返回。
- **解决方案**：导出 `MAX_IMPORT_CHARS`，解析前按字符数返回 errorTooLarge。
- **验证**：导入对话框错误文案用例。

#### D-05 VOICE 号码误判工作电话（P2）

- **根因**：解析器 `WORK || VOICE` 一律路由 workPhone。
- **解决方案**：CELL/HOME/无参 → 手机；WORK 且非 CELL → 工作。
- **验证**：vcardParse 新增两组用例。

#### D-06 制表符未剥离（P3）

- **解决方案**：`esc()` 与 `stripControlChars` 清洗区间补 `\t`；后者接入 `mergeWithDefaults`。

#### D-07 预览服务缓存导致误判（过程问题）

- **现象**：浏览器实测「修复未生效」。
- **根因**：`vite preview` 长驻进程内存缓存旧 index.html，哈希资产已更新但入口未更新。
- **解决方案**：重启预览服务复测；教训：长任务中预览服务需随重建重启。

> 触发原因：v0.1.0 首轮交付时 typecheck / lint / 56 项测试全绿，但深度审计发现**测试全绿 ≠ 功能可用**——原有二维码单测只断言「SVG 里出现了 `<rect>` / `<circle>` 标签」，从未验证生成的二维码真的能被扫描。据此改用真实解码器 + 浏览器实测补测，定位并修复 7 项缺陷。

### 问题闭环

#### A. 二维码「圆角」样式无法扫描（默认样式失效）

- **现象**：默认「圆角」样式的名片二维码在手机相机 / 微信扫码识别失败或极慢；「圆点」样式在全部测试载荷下 0% 可解码。
- **根因**：`src/lib/qr.ts` 将模块画为 `0.9×0.9 rx=0.26`（圆角）与 `r=0.44`（圆点），即在 1×1 单元内缩小墨迹。QR 码深色模块必须彼此连通才能被二值化；缩小后相邻模块间出现白缝，实测墨迹覆盖率 38.4% → 26.3%。模块数越多越明显，57 模块的中文名片即失效。
- **解决方案**：圆角改为填满单元仅磨角（`1×1 rx=0.25`）；圆点改为互相重叠（`r=0.62`）。以 jsQR 对 5 种载荷 × 4 档缩放做根因定位，再以 11 组半径 / 圆角参数扫描选出兼顾可扫与观感的取值。
- **验证**：`tests/qr.test.ts` 新增几何锁定用例；30 张真实名片 × 3 样式 × 3 尺寸 = 270 组合实测 270/270 解码成功。

#### B. PNG 导出 2048px 无法扫描

- **现象**：同一张名片 512px / 1024px 导出可扫，2048px 反而失败。
- **根因**：`renderQrPng` 生成 12px/模块小 SVG 后以最近邻放大到目标尺寸；模块数不能整除目标尺寸时相邻模块宽度不同（28px 与 29px 混排），网格对齐被破坏。
- **解决方案**：`renderQrSvg` 新增 `pixelSize`，按目标尺寸直接光栅化，`renderQrPng` 1:1 拷贝。
- **验证**：新增单测 + 270 组合实测 + 浏览器实际下载文件解码成功。

#### C. 小尺寸导出密名片不可扫

- **现象**：备注约 380 字节以上的名片选 512px 导出，扫码失败；三种样式同样失败。
- **根因**：QR 版本随内容增长，512px 分摊到 100+ 模块后每模块不足 5px，低于 ISO/IEC 18004 的 4px/模块下限与手机相机实际所需（约 6px）。属分辨率边界，非渲染缺陷。
- **解决方案**：新增 `QR_MIN_PIXELS_PER_MODULE = 8`，`renderQrPng` 将请求尺寸视为下限，过密时自动放大；新增 `pngReadyEnlarged` 提示文案与 `QrPngResult.raised` 标志，文件名使用实际尺寸，不谎报。
- **验证**：新增单测；浏览器实测请求 512px → 实际 1448px，解码成功并显示「名片内容较密，已按 1448px 导出以保证可扫」。

#### D. 草稿自动保存无限循环

- **现象**：页面打开后无任何操作仍持续写 localStorage 并重渲染，实测 5 秒 4 次，约每 1.2 秒一次，直至关闭页面。
- **根因**：`useLocalStorage` 每次渲染返回新的 `update` 函数；`Generator.tsx` 的自动保存 effect 将 `setDraft` 列入依赖数组，形成「渲染 → effect → setDraft → 渲染」闭环。
- **解决方案**：`update` 以 `useCallback` 固定身份。
- **验证**：浏览器实测修复后空闲 8 秒 0 次写入，草稿仍正确落库。

#### E. 导出再导入丢失全部「工作」字段

- **现象**：工作电话 / 工作邮箱 / 工作网站导出 .vcf 后导入，三项全为空。
- **根因**：写侧输出无参数的原生 `TEL:` / `EMAIL:` / `URL:`，读侧靠 `TYPE=WORK` 区分主 / 工作，写侧从不带参数 → 读侧永远判「主」，且 `take()` 只接受首个值，第二个被静默丢弃。
- **解决方案**：写侧补齐 `TYPE=CELL/WORK/INTERNET`。
- **验证**：新增单测；新增 `tests/roundTrip.test.ts` 全字段往返。

#### F. LOGO 串位与展示字段丢失

- **现象**：Logo 导出再导入后落在「照片 URL」；「品牌简称」「标语」导出后永久丢失。
- **根因**：解析器 `case "PHOTO": case "LOGO":` 共用分支都写入 `photo`；`companyShortName` / `slogan` 无 vCard 标准属性，写侧直接丢弃。
- **解决方案**：LOGO 独立分支写 `logoUrl`；新增 `X-SMARTVCARD-SHORTNAME` / `X-SMARTVCARD-SLOGAN` 实验属性承载展示字段（通讯录 App 会忽略未知 `X-` 属性，不影响互操作）。
- **验证**：新增单测 + round-trip 套件（含二次导入幂等）。

#### G. 导入对话框重复选同一文件无反应

- **现象**：导入超大文件报错后，再次选择同一文件无响应。
- **根因**：失败路径未重置 `event.target.value`，浏览器不触发 `change`。
- **解决方案**：读文件前统一清空 input。
- **验证**：代码审查 + lint。

## 2026-11-08 · v0.1.0 正式版首交付

### 问题闭环

#### 1. 分享链接扫码后打不开

- **现象**：默认「网页链接」二维码扫码后无法进入分享页。
- **根因**：`buildShareUrl` 把 `?v=` 放在 hash 之前，`HashRouter` 的 `useSearchParams` 读不到；且未携带当前路径。
- **解决方案**：改为 `${origin}${pathname}#/?v=…`；`App.tsx` 与 `readShareParam` 兼容旧链接。
- **验证**：`tests/cardShare.test.ts`；浏览器生成链接后新页打开，分享页正常。

#### 2. 中文 / 特定长度分享链接偶发解码失败

- **现象**：`decodeShareParam` 返回 null。
- **根因**：base64url padding 公式错误，且使用 `unescape/escape` 处理 Unicode。
- **解决方案**：`TextEncoder/TextDecoder` + 正确 padding。
- **验证**：多长度含中文样本 round-trip 通过。

#### 3. 长备注导致整页崩溃

- **现象**：全局错误覆盖层出现。
- **根因**：`useQRCode` 未捕获 qrcode 超限异常。
- **解决方案**：新增 `QrCapacityError`、`useQrPreview` 状态化、`too-long` 提示。
- **验证**：`tests/qr.test.ts`；浏览器超长输入不再崩溃。

#### 4. 中文界面英文名被排反

- **现象**：英文姓名在中文界面显示为「姓在前」。
- **根因**：顺序由 UI 语言决定。
- **解决方案**：按名字是否含 CJK 判定，卡片与 vCard 共用 `formatFullName`。
- **验证**：`tests/text.test.ts`、截图复核。

#### 5. 桌面端交付按钮被内部滚动裁切

- **现象**：右栏被 `max-h + overflow` 限制，导出按钮需要滚动才能看到。
- **根因**：初版右栏设计为整体 sticky + 内部滚动。
- **解决方案**：拆为「右侧固定校样」+「表单下方整幅交付台」。
- **验证**：1440×1000 截图确认交付台完整。

#### 6. 预览页仍显示旧版布局

- **现象**：重新构建后浏览器仍展示旧产物。
- **根因**：Service Worker 缓存 + 旧预览进程。
- **解决方案**：换新端口（4174）并重新加载；确认新交付台渲染。
- **验证**：截图核对。

#### 7. `npm test` 报 `ERR_MODULE_NOT_FOUND`

- **现象**：Node 无法解析 `./schema` 等无扩展名导入。
- **根因**：Vite 允许无扩展名，Node ESM 不允许。
- **解决方案**：`scripts/node-test-resolver.mjs` 用同步 `registerHooks` 补全扩展名；`package.json` 测试脚本加 `--import`。
- **验证**：56 项测试全部通过。

#### 8. `npm run build` 报 qrcode `mode` 类型错误

- **现象**：`QRCode.create` 不接受 `mode` 选项。
- **根因**：`@types/qrcode` 要求通过分段数组指定 byte 模式。
- **解决方案**：改为 `QRCode.create([{ mode: "byte", data: new TextEncoder().encode(text) }])`。
- **验证**：构建通过。

#### 9. `npm audit` 走镜像报 `NOT_IMPLEMENTED`

- **现象**：镜像未实现 audit 接口。
- **根因**：默认 registry 为 npmmirror。
- **解决方案**：`npm audit --registry=https://registry.npmjs.org`。
- **验证**：生产依赖 0 漏洞。

#### 10. 测试样本自身写错

- **现象**：断言失败但实现正确。
- **根因**：样本中姓名顺序、折行续行未以空格开头、`__proto__` 在对象字面量中不成为自有属性。
- **解决方案**：修正测试样本；补充 Node 版本要求说明。
- **验证**：56 项测试通过。

#### 11. ESLint `no-control-regex`

- **现象**：控制字符清洗正则触发 lint 错误。
- **根因**：规则默认禁止控制字符正则。
- **解决方案**：在确有需要的位置加 `eslint-disable-next-line no-control-regex` 并注释原因。
- **验证**：lint 0 错误。

#### 12. 历史文件归档

- **根因**：迭代遗留。
